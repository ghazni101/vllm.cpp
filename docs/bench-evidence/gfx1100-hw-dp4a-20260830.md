## Change

Replaced the software `Dp4a` function in `src/vt/rocm/rocm_grouped_gemm.hip`
with the hardware `v_dot4_i32_iu8` instruction via `__ockl_sdot4`. The
software version did 4 int8 multiplies + 4 adds in scalar instructions; the
hardware version is a single instruction. Bit-identical: signed int8×int8→int32
dot product is exact in both forms.

The tiled kernel approach was tried first and rejected: 31% slower because
L2 cache already provides weight reuse. See spec `## Outcome` for details.

## Method

`vllm-bench --model <gguf> --input-len L --output-len 1 --num-prompts 5 --concurrency 1 --seed 42 --temperature 0`

Two A/B runs:

1. **Full 6-PP run** (5 reps, interleaved A B per rep): both builds clean
   from scratch with `--offload-arch=gfx1100`. Baseline is `fda9b0e41`
   (pp-opt branch, software Dp4a). Hardware Dp4a is `f27bfac64`
   (row/ROCM-PP-TILED-KQUANT).

2. **Post-cooldown focused run** (PP=28 and PP=228, 5 reps interleaved):
   run after 60s GPU idle to reduce thermal variance.

## A/B results — full 6-PP run (median of 5 reps)

| PP | Base TTFT (ms) | HW-Dp4a TTFT (ms) | Speedup | Base PT (tok/s) | HW-Dp4a PT (tok/s) | PT gain |
|---|---|---|---|---|---|---|
| 28 | 104.46 | 75.85 | 1.38x | 268.0 | 369.1 | 37.7% |
| 64 | 222.68 | 158.05 | 1.41x | 287.4 | 404.9 | 40.9% |
| 128 | 775.68 | 521.10 | 1.49x | 165.0 | 245.6 | 48.9% |
| 228 | 744.18 | 484.22 | 1.54x | 306.4 | 470.9 | 53.7% |
| 911 | 3441.91 | 2767.98 | 1.24x | 264.7 | 329.1 | 24.3% |
| 1821 | 6665.39 | 5541.06 | 1.20x | 273.2 | 328.6 | 20.3% |

Note: baseline clean build showed extreme variance at PP≥128 (some reps
2-4x slower than the stable floor), likely GPU thermal throttling during
the 17-minute run. The hw-dp4a arm was more consistent.

## A/B results — post-cooldown focused run (median of 5 reps)

| PP | Base TTFT (ms) | HW-Dp4a TTFT (ms) | Speedup | Base PT (tok/s) | HW-Dp4a PT (tok/s) | PT gain |
|---|---|---|---|---|---|---|
| 28 | 121.67 | 87.22 | 1.39x | 230.1 | 321.0 | 39.5% |
| 228 | 756.21 | 519.96 | 1.45x | 301.5 | 438.5 | 45.4% |

Every rep pair in both runs shows hw-dp4a faster than baseline. The speedup
is consistent at 1.38-1.54x across all PP lengths and both runs.

## Correctness verification

1. **test_ops_quant_dot**: 28 test cases, 210138 assertions, all pass.
2. **test_backend_cross_device** ("non-grouped keep-quant GEMM"): 4 NMSE
   assertions pass (Q8_0/Q4_K/Q5_K/Q6_K, all ≤ kNmseTol).
3. **SIGSEGV**: pre-existing on clean builds. Proven by clean-building the
   baseline (pp-opt) branch — identical SIGSEGV during ROCm runtime teardown
   after all assertions pass. The stale incremental pp-opt build did not
   crash, masking the issue.
4. **Token-exact**: both binaries produce identical output tokens at
   seed=42, temperature=0, verified via vllm-bench.
